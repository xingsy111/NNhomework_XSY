## 三、实验原理
### 1. 线性量化（Linear Quantization）原理
量化的本质是将浮点数（FP32）映射到低比特整数（INT8），从而减少存储和计算开销。非对称线性量化的公式如下：

$$q = \text{clamp}\left(\text{round}\left(\frac{x}{s}\right) + z,\ 0,\ 2^{b}-1\right)$$

$$s = \frac{x_{\max} - x_{\min}}{2^{b} - 1}, \quad z = \text{round}\left(-\frac{x_{\min}}{s}\right)$$

其中：
- $x$ 为原始浮点张量，$q$ 为量化后的整数（uint8，范围 $[0, 255]$）
- $s$（scale）为缩放因子，$z$（zero_point）为零点偏移
- $b$ 为量化位数（本实验 $b=8$）

反量化（恢复浮点）的公式为：

$$\hat{x} = (q - z) \cdot s$$

对应的手写代码实现：
```python
def linear_quantize(x, num_bits=8):
    qmin, qmax = 0, 2 ** num_bits - 1
    min_val, max_val = x.min().item(), x.max().item()
    scale = (max_val - min_val) / (qmax - qmin)
    zero_point = qmin - round(min_val / scale)
    zero_point = int(max(qmin, min(qmax, zero_point)))
    q = torch.round(x / scale) + zero_point
    q = torch.clamp(q, qmin, qmax).to(torch.uint8)
    return q, scale, zero_point
```

### 2. INT8 静态量化流程
PyTorch的INT8静态量化（Static Quantization）包含四个关键步骤：

- **模块融合（Fuse）**：将相邻的 `Conv+ReLU` 或 `Linear+ReLU` 融合成单一算子，减少计算次数并提高量化精度。
- **准备（Prepare）**：在模型中插入量化观察器（Observer，如MinMaxObserver），用于在校准阶段统计激活值的范围。
- **校准（Calibrate）**：用少量真实数据（1000张）前向推理，让观察器收集每层激活的 `min/max`，从而计算出每层的 scale 和 zero_point。
- **转换（Convert）**：将观察器替换为真正的量化/反量化算子，把FP32权重转换为INT8整数。

对应代码：
```python
int8_model.fuse_model()                       # 模块融合
int8_model.qconfig = torch.quantization.default_qconfig
prepare(int8_model, inplace=True)             # 准备
with torch.no_grad():                          # 校准
    for imgs, _ in calib_loader:
        int8_model(imgs)
convert(int8_model, inplace=True)             # 转换
```

### 3. 模块融合（Module Fusion）
本实验模型包含6个卷积层和2个全连接层，每层后面都接ReLU激活函数。融合后，`Conv+ReLU` 变为单个融合算子，消除了ReLU的额外计算开销，同时由于ReLU的输出非负，融合后量化范围估计更准确，有助于提升量化精度。

## 四、实验步骤
1. **环境配置**：在本地Windows环境配置PyTorch（CPU版本），确认INT8量化仅在CPU上支持。
2. **权重准备**：运行 `train_hw2.py` 重新训练SVHN的CNN模型，生成FP32权重文件 `svhn_cnn_fp32.pth`（测试准确率95.12%）。
3. **手写量化函数验证**：实现 `linear_quantize` 与 `linear_dequantize`，用随机张量测试其正确性与量化误差。
4. **FP32基线评估**：加载原始FP32模型，在测试集上评估准确率、CPU推理延迟和模型文件大小。
5. **构建可量化模型**：将原始的 `nn.Sequential` 结构展开为独立命名的卷积层，添加 `QuantStub`/`DeQuantStub` 量化桩，并将FP32权重映射加载到该模型。
6. **模块融合**：对7组 `Conv+ReLU` 和 `Linear+ReLU` 执行融合。
7. **校准**：用1000张训练集样本进行前向推理，统计各层激活范围。
8. **INT8转换与评估**：转换为INT8模型，重新评估准确率、延迟和大小，与FP32对比。
9. **量化误差分析**：通过前向钩子（forward hook）收集FP32与INT8模型各层输出，计算逐层MSE误差。
10. **可视化**：绘制准确率、延迟、模型大小、各层MSE四张对比图，保存为 `quantization_results.png`。

## 五、实验结果与分析

### 1. 手写量化函数正确性验证
对一张 4×4 的随机浮点张量进行量化与反量化，结果如下：

| 指标 | 数值 |
|------|------|
| 量化参数 scale | 0.015813 |
| 量化参数 zero_point | 133 |
| 量化-反量化误差 MSE | 0.000016 |
| 最大绝对误差 | 0.007506 |

误差极小，验证了手写线性量化函数实现正确。

### 2. FP32 vs INT8 核心指标对比

| 指标 | FP32 模型 | INT8 模型 | 变化 |
|------|-----------|-----------|------|
| **测试准确率** | 95.12% | 95.16% | **+0.04%（无损）** |
| **CPU推理延迟（单张）** | 5.68 ms | 2.48 ms | **加速 2.29×** |
| **模型文件大小** | 5.12 MB | 1.29 MB | **压缩 3.96×** |

### 3. 结果分析
1. **精度几乎无损**：INT8量化后准确率非但没有下降，反而略升0.04个百分点（在统计误差范围内）。这表明对于SVHN这类简单分类任务，CNN模型对量化非常鲁棒，模块融合（Conv+ReLU）和静态量化（先校准后量化）有效控制了精度损失。
2. **推理显著加速**：INT8模型在CPU上的单张推理延迟从5.68ms降至2.48ms，加速约2.3倍。这是因为INT8整数运算比FP32浮点运算更快，且模块融合减少了算子数量。
3. **模型体积大幅压缩**：权重从32位浮点（4字节）压缩为8位整数（1字节），理论压缩比4×，实测3.96×，与理论值高度吻合。这极大降低了模型的存储和传输成本，有利于在边缘设备上部署。

### 4. 手写量化 vs PyTorch量化（权重误差）
对FP32模型每一层权重分别应用手写量化，观察权重自身的量化误差：

| 层名 | scale | zero_point | 权重MSE | 最大误差 |
|------|-------|-----------|---------|---------|
| conv1 (features.0) | 0.002680 | 124 | 6.2e-07 | 0.001338 |
| conv2 (features.2) | 0.002530 | 147 | 3.0e-07 | 0.001265 |
| conv3 (features.6) | 0.002742 | 166 | 2.9e-07 | 0.001371 |
| conv4 (features.8) | 0.002903 | 146 | 2.5e-07 | 0.001451 |
| conv5 (features.12) | 0.003095 | 158 | 2.6e-07 | 0.001547 |
| conv6 (features.14) | 0.002680 | 135 | 2.4e-07 | 0.001340 |
| fc1 (classifier.1) | 0.002202 | 138 | 1.4e-07 | 0.001101 |
| fc2 (classifier.4) | 0.001965 | 139 | 2.5e-07 | 0.000982 |

各层权重量化误差均在 $10^{-7}$ 量级，最大绝对误差仅约0.0015，说明8位量化对权重的表达能力完全足够。

### 5. 各层量化输出误差（MSE）分析
对比FP32与INT8模型在同一批数据上的逐层输出：

| 层 | 输出MSE |
|----|---------|
| conv1 | 1.66e-05 |
| conv2 | 3.53e-05 |

| conv5 | 1.40e-04 |

分析：随着网络加深，量化误差逐层累积（conv层MSE从 $10^{-5}$ 增至 $10^{-4}$）；最后的全连接分类层 `fc2` 误差最大（0.0187），这是因为它是logits输出层，数值范围最大、对量化最敏感。但即便如此，由于 `argmax` 分类决策对小幅数值扰动不敏感，最终准确率未受影响。
